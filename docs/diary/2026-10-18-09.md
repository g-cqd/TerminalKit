# Diary — 2026-10-18 (09)

## Hot-path ceilings for the router and the frame flush

Aemi `a6446f1` counts only the measuring thread (Aemi ADR-0010): a fresh thread's 10,000
allocations had added 10,008 to a window's count. TerminalKit now pins it.

A throwaway probe measured realistic workloads before any limit was written. Text and single
keystrokes were already free; every other key kind allocated 1–3 times, a paste 5, a flush 4–11.
Tests written next, all failing with exactly those counts, then the fixes (ADR-0016):

- `buffer = [byte]` on ESC and `utf8Buffer = [firstByte]` threw away retained capacity;
- `decodeKeyboardSequence` returned an array; `MouseDecoder.reset` released its buffer;
- a paste's `dropLast` slice outlived the expression and forced `resetRouting` to copy the buffer;
- `dirtyRanges` built a growing array every flush;
- `OSSignposter` intervals cost 3 allocations each, and `isEnabled` is true by default, so guarding
  on it changed nothing. Bisecting the flush found this: removing the signpost block took an idle
  flush from 3 to 0. `os_signpost` with an `OSSignpostID` measured 0.

Wrong hypotheses along the way, recorded so they are not retried: the main-actor isolation check
(measured 0) and `writeContiguous`/`adoptDirtyCells` (bisected out, 0 each).

The decoder's opt-in gate and its CI job are removed; all ceilings run in the release gate,
disabled in debug. Gate: 397 tests, seven executables, exit 0, every allocation test executed
(job `job-199`). The stale `lane/alloc-guard` worktree and branch were removed after their merge.
