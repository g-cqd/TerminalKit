# Diary — 2026-10-18 (06)

## The decoder allocated once per keystroke

Branch `lane/alloc-guard`, worktree `/tmp/tk-alloc-guard`. A parallel session is editing
TerminalKit's `SignalHandler` in the main tree and its work does not compile, so this work was done in
a worktree rather than beside it.

Measured over 1,000 keystrokes with Aemi's counter, on the thread that opens the window:
**1,335 allocations before, 0 after.** The cause was `removeAll()` releasing the buffer's storage so
the next `append` reallocated; `keepingCapacity: true` fixes it and costs nothing.

The counter was validated first, and one of my probes was wrong: it expected 1,000 allocations from
1,000 array appends and got 12, because `Array` growth is amortised. The counter was right; the
expectation was not.

## A ceiling needs an empty process

The guard is `count == 0`, with a control that must detect an allocation.

It cannot live in the default suite. Measured: in isolation the decoder's 0 allocations read as 0;
inside the full suite the same measurement read as **101**, from other suites' threads that start
inside the window. Judged against that number, the ceiling would be a ceiling on the test runner.

So the tests are opt-in (`TERMINALKIT_ALLOC=1`), the suite is `.serialized` so its own two tests do
not contaminate each other — without that the control's 100 strings landed in the decoder's window
and the gate failed at 101 — and CI runs them in a job of its own.

Mutation check: reverting the fix reports exactly 1,000 allocations for 1,000 keystrokes and fails;
restoring it reports 0 and passes.

`minimumAllocations(repeats:body:)` was added to Aemi rather than copied here: it takes the minimum
across repeats because contamination can only push a count up, and the minimum is the conservative,
stable sample to judge a ceiling against.
