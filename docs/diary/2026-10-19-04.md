# Diary — 2026-10-19 (04)

## Roadmap 0010: terminal modes as a unit

`TerminalSession` enters a `TerminalModes` value in one write and leaves it in one write. Decision:
ADR-0019.

## Probes

| Claim | Probe | Verdict |
|---|---|---|
| The router already decodes `CSI 27 u` as Escape | `the disambiguated Escape key decodes as Escape`, run before any change | **CONFIRMED**: passed on the old code |
| kitty sends Escape as `CSI 27 u` once flag 1 is pushed | `verify-keyboard-protocol.sh`: kitty remote control sends a real Escape | **CONFIRMED**: `\x1b[27u` |
| Keyboard flags are per screen | push on the alternate screen, query `CSI ? u` on each screen | **CONFIRMED** on kitty and ghostty: 1 on the alternate screen, 0 on the main |
| Unpopped flags stay behind on the alternate screen | leave without popping, re-enter, query | **CONFIRMED** on both: 1. The pop must precede `?1049l` |
| The pop-order test can fail | move the pop after `?1049l` | **CONFIRMED**: three tests fail through the model |
| The SIGTERM path and the normal path exit once | signal-thread `leave()`, then the normal `leave()` | **CONFIRMED**: one `termios` restore, every mode off |

The model gained per-screen kitty keyboard stacks. Before, `CSI > 1 u` would have been read as the text
"1u", because its parameter loop stops at `>`.

## Red

Twenty expectations failed against a stub with the final API: no bytes written, no flags dropped, no
restore. `the keyboard flags are popped on the screen they were pushed on` passed vacuously against the
stub, so the negative control above is what proves it.
