# Diary — 2026-10-19 (12)

## Roadmap 0014: who owns the pipeline

Decision and tables: ADR-0026. The user's brief: not the main thread, input never blocked, rendering kept
going, both ownerships stress-tested.

| Claim | Probe | Verdict |
|---|---|---|
| The pipeline can leave the main actor | `PipelineIsolationTests` on a plain `Thread` and in an actor | **CONFIRMED** after removing `@MainActor`; every existing test still passes |
| Ask's design (one frame per event) holds up under load | `IsolationProbe`, 2 ms composer, 5,000 lines/s | **REFUTED**: a keystroke waits 2 s, 3,610 events queued. Fine at 0.1 ms |
| A thread is what fixes it | same, A′ (main actor, coalescing) | **REFUTED as stated**: coalescing alone fixes the collapse. The thread adds what coalescing cannot |
| …which is input handling that never waits for a frame | a 40 ms frame every 100 lines | **CONFIRMED**: 0.02 ms against 37 ms |
| …and rendering the main actor cannot starve | main actor 50 % busy | **CONFIRMED**: 1,491 frames against 888 |
| The thread slows the idle case | idle and light-load rows | **REFUTED**: identical within noise |
| The shipped loop behaves as the prototype | design C beside B, same rows | **CONFIRMED** |
| Signposts are free | one-cell flush with and without | **REFUTED**: 0.46 µs, more than the frame's own work |
| `OSLog.signpostsEnabled` tells us when to skip them | gating on it, then the benchmark | **REFUTED**: always true; no change |

## Mistakes of mine

- The probe's first numbers were partly an artifact: its render thread stopped at the deadline while the
  event loop's last event arrived after it, so one run said "final state not shown". It now stops when its
  events have.
- The CPU column counts the producer thread spinning to pace itself, so every row reads about 1,000 ms a
  second higher than the work it measures. It is in the output but not in the ADR.
- Frames are timed in the shipped loop at compose, not flush: a few microseconds optimistic.
