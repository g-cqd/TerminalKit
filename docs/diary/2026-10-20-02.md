# Diary — 2026-10-20 (2)

## Probing the mouse, the clipboard and graphics in four terminals

The owner answered the open defaults ("starts folded") and asked for the probes and the work on every topic. This is the probe.
Result and decisions: ADR-0028. The probe: `Scripts/probe-interaction.sh`, `probe-interaction.py`, `mouse-inject.swift`,
`analyze-interaction.py`.

| # | Claim | Probe | Verdict |
|---|---|---|---|
| 1 | OSC 52 writes land on the clipboard, at any size | write 16 B to 1 MB inside each terminal, read the macOS pasteboard back | **kitty, Ghostty, WezTerm: yes, exact to 1 MB. Terminal.app: never** |
| 2 | WezTerm drops the first OSC 52 write | four windows whose first write was 16, 16, 1 and 16 bytes, then later writes (a fifth run could not show it: its results were keyed by size) | **CONFIRMED, 4 of 4**: the first is dropped after 2.5 s; later ones land in about 20 ms |
| 3 | Real mouse events reach the program, and Shift returns the terminal's own selection | OS-level `CGEvent`s posted into each window, decoded from the raw bytes | **kitty, Ghostty, WezTerm: Shift is not reported. Terminal.app: Shift is reported, and fn is not** |
| 4 | Option and Command are distinguishable | the same events with modifier flags | **No**: WezTerm sends Option without the alt bit; Terminal.app sends Command with no bit |
| 5 | With reporting off the wheel becomes arrow keys | the same scroll with reporting off, in the alternate screen | **CONFIRMED**, in different amounts: 15, 9, 3 per injected scroll (kitty, Ghostty, WezTerm) |
| 6 | Redrawing images each frame is cheap to parse | delete and place 0, 4 and 16 images then wait for a device-status reply, 100 frames each | **CONFIRMED**: under 2 ms added; drawing cost not measured |
| 7 | Terminal.app draws images | kitty graphics query | **No** |

### What went wrong

The probe had five bugs of mine before it measured anything, each found by looking at an empty result and not by trusting it:

- the image bytes were built from tuples, so the graphics mode died and the harness waited on a window that had exited;
- the harness looked for `kitty.mouse.ready` while the probe wrote `kitty.json.mouse.ready`, so no mouse event was ever injected;
- WezTerm's windows are owned by `wezterm-gui`, not `WezTerm`;
- Terminal.app's window was not on screen until I activated it and set its bounds;
- the OSC 52 results were keyed by size, so repeating a size overwrote the first outcome, which is the one that mattered.

I also opened four terminal windows, one after another, on the owner's machine, for about a minute each.
