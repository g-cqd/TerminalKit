# Diary — 2026-10-24 (1)

## A legacy CSI key's modifier was read as 12 instead of 2

Found by ask, through a real PTY: Shift with an arrow key (`ESC [ 1 ; 2 C`) reached the host with Shift, Alt **and** Super set. ask's
selection keys, which check that only Shift is held, never fired in the real binary, though they passed with hand-built events.

### Cause

`SequenceRouter.parsedCSIParams` starts the modifier at 1, because the wire value is one-based (1 means none), and then appends digits to
it as they arrive. `2` becomes `1 × 10 + 2 = 12`, and 12 − 1 = 11 is Shift | Alt | Super. Every digit-bearing modifier was wrong:
`;3` read as 13 (12 → Ctrl and Super), `;5` as 15, and so on. A plain `ESC [ A` and an empty `ESC [ 1 ; C` were right because no digit was
appended. The kitty `CSI u` decoder is a different path and was not affected.

### Fix and evidence

The modifier is zeroed when the `;` that introduces it is seen, so appended digits give the number sent; with no `;` it stays 1 (none).
`SequenceRouterModifierTests` (11 cases): eight arrows (none, Shift, Alt, Ctrl, Shift+Ctrl, Super, Shift+Super, and an empty modifier),
three tilde keys, and the event type after a colon (release, repeat). Run against the old code, nine of the eleven failed (the plain arrow and
the empty modifier passed, as predicted); against the fix, all pass, with the rest of the router and input-source suites (42 tests).

### Not checked

Whether anything else in a host relied on the wrong values (ask did not: it uses no modifier but Shift and Ctrl-letter). No benchmark was run:
the parser does the same work, with one more store when a modifier is present.
