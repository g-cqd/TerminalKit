# Diary — 2026-10-20 (5)

## Roadmap 0018: the fold model and the scroll rule

Decision: ADR-0031. Code: `Foldable.swift` and `ScrollAnchor.swift` in TerminalKitText; tests `FoldTests`. The model and the arithmetic, not the
drawing and not images.

| # | Claim | Probe | Verdict |
|---|---|---|---|
| 1 | A block cannot fold to nothing | the type: there is no initializer without a placeholder | **BY CONSTRUCTION**; the test checks what a placeholder carries |
| 2 | Folding a block above the viewport does not move the reader | the same anchor before and after a fold, with the anchor on the top row, on another row, in the folded block, and below the change | **CONFIRMED** in each, and unfolding returns to where it was |
| 3 | It holds in general, not only in my examples | 500 random stacks, viewports, anchors and folds, deterministic seed | **CONFIRMED**: the anchored row keeps its screen row unless the offset hit the top or the bottom, where it equals the clamp |
| 4 | The tests can fail | five mutations | **ALL CAUGHT**, after redoing one that did not compile |

### What went wrong

- **One of the five mutations did not compile** (it left a variable unused), which proves nothing, so it was redone. This is the third time in this
  work that a bad mutation looked like a result.
- **The property test assumes the host takes the anchor before the change.** The kit cannot enforce that, and a host that takes it after will
  scroll by the wrong amount. It is a convention, written in the documentation, and nothing tests a host.
