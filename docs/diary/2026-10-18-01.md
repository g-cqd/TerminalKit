# Diary — 2026-10-18 (01)

Part 1.

## Where things stand

`TerminalKit` is a new repository holding the terminal stack, moved out of Atelier's
`Apps/KittyCode`. It has two products already: `TerminalKitCore`, with the tiered reset ladder, and
`TerminalKitTestSupport`, with the oracle terminal model. Seventeen tests, all green.

It has **zero external dependencies**. That is deliberate and temporary: the Aemi dependency arrives
with the extraction, because `KittyCodecs` and `KittyInput` genuinely import `AemiKernel`, and not one
moment before.

## Why the terminal left Aemi

`AemiTerminalCore` was landed in Aemi first, in two commits, before the placement had been questioned.
Moving it afterwards would have looked like churn, so the question was asked anyway, and the answer
changed.

Aemi's manifest describes it as the kernel package and splits its targets into kernel runtime tiers
(`AemiKernel`, `AemiText`, `AemiIO`, `AemiRuntime`, `AemiUnicode`, `AemiMetrics`, `AemiKernels`,
`AemiMacroSupport`) and application tiers (`AemiCore`, `AemiUI`, `AemiTesting`), and says explicitly
that the two stay apart. Terminal is neither. It is a third thing: an escape-sequence grammar, a
capability negotiation, a reset lifecycle. Putting it inside Aemi stretches a boundary Aemi already
has to defend, for no gain.

The manifest-graph cost is real but only partly relieved, and it is worth stating precisely rather
than claiming a win. `AemiKernel` is zero-dependency, but SwiftPM resolves a package's entire manifest
no matter which target is linked — so any consumer of `AemiKernel` resolves swift-syntax 603..<605 and
its macro tree anyway. Once the extraction lands, TerminalKit will depend on `AemiKernel`, and
therefore on Aemi. The separation buys an independent cadence and a focused manifest; it does not buy
independence from Aemi, and the ADR says so.

Aemi has **zero tags**. Terminal work is the fastest-moving thing in the ecosystem, and making it wait
on a repository with no releases is a drag worth removing.

The name is `TerminalKit` rather than `AemiTerminal` for exactly this reason. With its own repository,
an `Aemi` prefix would assert an ownership that no longer exists.

## What the probes overturned

**The seam was guessed from module names.** `KittyTerminal`, `KittyCodecs` and `KittyRenderer` looked
like the terminal stack. Grepping their imports found `KittyStyle` and `AtelierText` — and
`AtelierText` lives in a *different package*. Following the closure pulled in `KittyInput` too. The
seam is six modules and 6,263 lines, not three and 3,530: **79% larger than the plan claimed.**

**Two escape sequences were malformed.** `ESC [ ? 1006 l` and `ESC [ ? 2004 l` were each written a byte
short. Both look like plausible byte soup; neither survives inspection reliably. Left alone, a crash
would have left the user with mouse reporting and bracketed paste still switched on — the precise
failure the ladder exists to repair. The byte-exact test found it on its first run.

Reading the arrays three times did not find it. Printing the bytes and comparing index by index did, in
one run. The claim "these sequences are right" had only ever been supported by my own transcription of
them.

**The oracle found a bug in the oracle.** Mode 25 is inverted relative to the other private modes:
`CSI ? 25 h` *shows* the cursor. The model had it the obvious way round, so it hid the cursor at the
exact moment the ladder was trying to show it. The failing assertion pointed at the test double rather
than the encoder, which is the whole reason for writing one — a single implementation agreeing with
itself is not evidence.

## What cannot be verified here, and is therefore still owed

`kitty @ ls` fails with `open /dev/tty: device not configured`. kitty 0.49.2 is installed, but this
session has no controlling TTY and no remote-controlled instance is reachable. So the reset tiers are
verified against a **model of a terminal**, not against a terminal. That gap is recorded in roadmap
0002 rather than papered over.

`openpty` is declared in the SDK (`util.h:99`), so a PTY harness is buildable; that has not been
attempted.
