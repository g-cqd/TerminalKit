# Diary — 2026-10-19 (06)

## Roadmap 0007: sixteen-byte cells

Decision and numbers: ADR-0021.

## Probes

| Claim | Probe | Verdict |
|---|---|---|
| Eight inline bytes hold practically every grapheme | 189,591,381 graphemes from 139 Claude Code and pi transcripts (225 MB), counted in Swift | **CONFIRMED**: all but 7 fit. 99.90 % are ASCII, 99.9998 % four bytes or fewer. The 7 are ZWJ emoji (rainbow flag, families, technologist) |
| A screen uses few styles | ask's `ScreenComposer`; KittyCode's colour scheme | **CONFIRMED** by reading: 6, and about 60 names |
| The repacking changes nothing the terminal receives | every existing frame and diff test, unchanged | **CONFIRMED**: 438 tests pass, byte-exact suites included, and every allocation ceiling holds |
| …except canonically equivalent spellings | a probe test on the old code: `é` over `e` + U+0301 | **CONFIRMED** as a change: old code, not dirty (red); new code, dirty. Kept as a test |
| Index lookup does not slow the diff | `benchmarks.sh compare HEAD` | **CONFIRMED**, and better: full-screen flush 5.9× faster, unchanged rewrite 6.3× |
| …and the one-cell flush improves too | same | **REFUTED**: 2.0 / 3.8 / 16 µs, as before. Its screen-sized cost is elsewhere (0008) |

## Notes

- `PackedCell.character` decodes through `withUnsafeBytes` over the inline word, so it builds no
  intermediate array.
- `GraphemeTable` is keyed by the exact bytes, not by `Character`, for the same reason the cells are.
