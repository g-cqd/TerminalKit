# Diary — 2026-10-19 (07)

## Roadmap 0011: scroll regions, detected

Decision and numbers: ADR-0022.

## Probes

| Claim | Probe | Verdict |
|---|---|---|
| A layout can just say how far its rows moved | read ask's composer and the pipeline | **Partly**: the composer knows the lines it added, not what the terminal shows after a resize, a redraw or a skipped frame. Detecting the shift needs no such bookkeeping |
| The scroll saves most of a streamed line's bytes | `stream/…` benchmark, first version | **REFUTED at first**: 413 → 291 bytes. The scrolled-in row was written word by word, with a cursor move over every space |
| Writing short gaps fixes that | the same benchmark, after `DiffGapTests` went red then green | **CONFIRMED**: 291 → 151 bytes |
| Detection is cheap | the same benchmark | **REFUTED at first**: 15 → 44 µs at 120×40, 63 → 214 at 300×80. Spans for the comparison and the shift, a non-chained row hash, and cached front-row hashes brought it to 22 and 98 µs |
| My benchmark transcript resembled ask's | first run: 22 bytes, no change | **REFUTED**: my lines were cut to the width before their number, so every line was the same. Switched to ask's own transcript lines |
| The pipeline draws the right screen in real terminals | `verify-scroll-region.sh`: kitty, wezterm, Terminal.app | **CONFIRMED**. The comparator can fail: shifting one expected row reports it |
| Hash caching stays correct across mixed frames | `a long run of mixed frames keeps the screen right`: edits, redraws, scrolls, replayed through an emulator | **CONFIRMED** |

## Tooling found on the way

- package-benchmark runs every executable under `Benchmarks/Benchmarks/` as a benchmark. The probe crashed
  the run there, so it lives in `Benchmarks/Probes/`.
- Terminal.app's `contents of <tab variable>` dereferences the variable. Reading the tab through its
  window works.
- wezterm's CLI must be pointed at the new GUI process's socket.
- `benchmarks.sh compare` could not build this tree's benchmarks at the base, because they use the new
  API. It now falls back to the base's own.
