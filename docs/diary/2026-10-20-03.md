# Diary — 2026-10-20 (3)

## Roadmap 0016: regions and click recognition

The first of the four interaction entries to get code. Decision: ADR-0029. Code: `PointerRegions.swift` and `PointerRecognizer.swift` in
TerminalKitInput; tests `PointerRecognizerTests`, `RecordedMouseStreamTests`, `PointerRecognizerAllocationTests`; benchmarks
`pointer/*` and `regions/hit` in the input suite.

| # | Claim | Probe | Verdict |
|---|---|---|---|
| 1 | The recognizer turns real terminals' reports into the right gestures | the streams recorded by the ADR-0028 probe, replayed through `MouseDecoder` and `PointerRecognizer` | **CONFIRMED** for kitty, Ghostty, WezTerm and Terminal.app, including that WezTerm produces no modifier and Terminal.app produces Shift and Option |
| 2 | The tests can fail | four mutations: no zero-based conversion, the wrong tie rule, a click count that never wraps, a click that ignores the target | **three caught at once; the fourth was missed** (see below) |
| 3 | Recognizing a report allocates nothing | allocation counter over 100 rounds of a click, a drag, a wheel step and motion, with 120 regions; and `hit` made to allocate on purpose | **CONFIRMED**: zero; the deliberate allocation fails all four checks |
| 4 | A hit test over 120 regions is cheap | the input benchmarks | **NOT AT FIRST**: 2,927 ns. The same code was 85 ns when compiled in one module with whole-module optimization |
| 5 | `@inlinable` fixes it | the same benchmark | **No**: 13% (2,927 to about 2,500 ns) |
| 6 | Moving the scan into a non-generic type fixes it | the same benchmark | **CONFIRMED**: 119 ns, and click 3,226 to 345, drag 718 to 161, wheel 3,117 to 230 ns per event |

### What went wrong

- **A test I wrote did not test what its name said.** "A release on a different target than the press is not a click" moved the
  pointer two rows, which is already a drag, so the click-versus-target branch was never reached and removing it changed nothing. I
  found it by mutating the code and seeing the suite stay green. The test was renamed for what it checks, and a new one moves the
  content under a still pointer.
- **My first mutation left the file broken.** The new source files were untracked, so `git checkout` could not undo the change. I
  restored it by hand and used backups for every later mutation.
- **I assumed `@inlinable` would fix the speed, and it mostly did not.** The experiment that separated the algorithm (85 ns) from the
  module boundary (2,927 ns) is what showed the real cause.
