# Diary — 2026-10-19 (01)

## What ask's first full-screen use measured, and the roadmap it produced

ask now renders its interactive screen through `RenderPipeline`. Measuring it turned up one fix, already
landed (3440cbd: the 393 KB digit table is now 4 KB), and the evidence behind roadmap 0006–0014.

## Measurements (release, M-series, from ask's Benchmarks package)

- **`Cell`:** size 35 B, stride 40 B (Character 16, Style 18).
- **Two grids:** 393 KB at 120×40.
- **Through `RenderPipeline` over `MockTerminalConnection`, one changed cell:**
  - 120×40: flush 3 µs;
  - 300×80: flush 15 µs.
  This is not proportional to the change (0008).
- **`ScreenBuffer.write` of an unchanged row:** about 16 ns per cell. 77 µs to rewrite 120×40, 380 µs at
  300×80, with a p99 of 27 ms (0007).
- **Streamed line in a bottom-aligned transcript:** 494 B at 120×40, 1,048 B at 300×80 (0011).

## Read from code

- `InputSource` blocks in `read()` inside a `Task`, holding a pool thread (0009).
- No owner for terminal modes: ask never enabled bracketed paste (0010).

## A correction to my own first attribution

My first benchmark said the diff cost 87 µs per keystroke. It composed into a fresh buffer, so every cell
was dirty, and it copied the front buffer each frame. The real pipeline walks only dirty ranges: 3 µs.
Measured again through `RenderPipeline` itself before writing anything down.
