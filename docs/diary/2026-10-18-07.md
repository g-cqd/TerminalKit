# Diary — 2026-10-18 (07)

## Safety correction before new features

Reading the published signal handler found `Mutex.withLock` in its OS callback. The comment claiming
that lock was safe is false: `man 2 sigaction` lists async-signal-safe functions and excludes such locks;
a signal can interrupt the thread already holding the mutex. Ordinary successful signal delivery did
not test this failure mode.

Red: `swift test -c release --enable-testable-imports --filter 'stopping an unstarted'`
returned 1: stopping a stranger incorrectly released the active owner's process-global state.
A second regression covers stopping an old owner twice after a new owner starts.

Green: eight signal tests pass. The OS callback now lives in `CTerminalSignals`, not Swift; always-
lock-free atomics and a nonblocking wakeup pipe keep Swift runtime and locks out of signal context.
A permanent reader/two descriptors avoid closing a descriptor under an in-flight callback. Old
pending bits carry a generation and cannot be applied to a new owner. Previous dispositions are restored.

`sh Scripts/verify-signal-safety.sh` passed saturation (100,000 raises without a reader), shutdown
coalescing, errno preservation, prior-disposition restoration and generation isolation. This runs
in its own process and is part of the quality gate. No sleeps are used.

`Scripts/quality.sh` returned 0: 393 reported tests across seven targets, plus the C probe. Tests that
were already gated/skipped remain so. No new unchecked Sendable conformance was introduced.

ADR-0015 supersedes ADR-0013 instead of rewriting the earlier decision to conceal the defect.
