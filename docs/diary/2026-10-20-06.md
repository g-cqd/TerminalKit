### What went wrong

- **One mutation did not compile again** (backward drag keeping the leading anchor: `after` became unused). It was redone with a form that
  compiles, and then failed one check. The fourth time.
- **My test was wrong, not the controller**: after a scroll of two rows I pointed at row 0 expecting "beta", but row 0 was the blank row between
  blocks and snapped to the start of the next block. The controller did the documented thing.
- **I wrote the controller against the kit's APIs from memory** and it compiled first time, which was more suspicious than reassuring. I
  checked the names and what `SelectionEdge` means before trusting it.
- `wrap/prose at 80` once looked 6% slower and once equal on the same code. The 15% gate and the unchanged allocation count are the evidence,
  not either single number.

### A bug that only a screen found

`RowMap.position` applied the trailing edge only when the column was right of the row's start, so the **first column** had no grapheme under it:
pressing at column 0 and dragging backwards left that grapheme out of the selection. The kit's own tests never pressed at column 0 on a backward
drag. ask's first screen test did (a drag from the start of a row up to a row above), and the copied text lost its last character. Fixed with
tests for the first cell on plain text, on a wide grapheme, left of the text, and on an empty line. The lesson is the one the roadmap keeps
asking for: a model tested only against its own helpers misses what a real layout does at its edges.
