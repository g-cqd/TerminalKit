# Diary — 2026-10-19 (03)

## Roadmap 0015: rst's reset techniques, probed

ask's study listed six things rst does on reset that TerminalKit does not. Decision: ADR-0018.

## Probes

| Claim | Probe | Verdict |
|---|---|---|
| `TCSAFLUSH` waits forever behind stopped output | PTY, `TCOOFF`, 100 B queued, 2 s timer | **CONFIRMED** (also `TCSADRAIN`) |
| `tcflow(TCOON)` first fixes it, as rst does | same | **CONFIRMED** for a stop |
| …and fixes an emulator that stopped reading | PTY with nobody reading the other side | **REFUTED**: still waits. Only `TCSANOW` returns |
| `TCSANOW` loses `TCSAFLUSH`'s input discard | typeahead, then read non-canonically | **CONFIRMED**; `tcflush(TCIFLUSH)` restores it |
| Queued output is reprocessed by the new flags | raw write, `TCSANOW` restore, read the other side | **REFUTED**: `a\nb\r\nc`, only the later write |
| A stop survives the restore | `TCOOFF`, `TCSANOW`, write | **CONFIRMED**: nothing arrives until `TCOON` |
| A background job changing `termios` is stopped | `pty.fork`, a child in its own group | **CONFIRMED**: `SIGTTOU` |
| TerminalKit's own restore hangs (red) | `TerminalRestoreTests` under `sample` | **CONFIRMED**: blocked in `tcsetattr` in `restoreMode` and in `enterRawMode` |
| Tier 1 resets `?2026` and `?1004` on real terminals | `verify-reset-ladder.py` in kitty, ghostty, wezterm | **CONFIRMED** |
| …and the `?2026` reset is tier 1's doing | The mode table read `?2026` reset even before tier 1 | **INCONCLUSIVE at first**: the update times out before the table reaches it. Added a control queried at once: set on kitty and ghostty, then reset by tier 1. wezterm does not answer during an open update |

A first mistake of mine: the "typeahead discarded" probe restored canonical mode before reading, so five
unterminated bytes looked like nothing in every case. Re-run reading non-canonically.

The red runs block forever, so they were observed by running the filtered tests in the background,
sampling the stack, and killing them. No test carries a timeout.

## Not adopted

The background guard (job control is the expected behaviour for a TUI), control-character repair
(TerminalKit restores what it saved), `?7h` and `4l` (nothing here sets them). Reasons in ADR-0018.
